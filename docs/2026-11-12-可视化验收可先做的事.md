验收把这道题收成按用例对标准答案。组织方提供至少 30 条轨迹，自己跑封版后的 Docker，收三个层面的截图或交互页、每条样本一份 JSON，以及运行日志。思维链只输出「有风险」或「无风险」，并要能定位到步骤原文。集成 2 分：只导入 OpenAI messages 得 1 分；再支持一种主流格式，且统计数值与标准答案一致，得 2 分。组织方只发 OpenAI 格式。

数据统计指标可视化共 6 分：

| 小项 | 分 | 要求 |
| --- | --- | --- |
| ① | 1 | 每条模型请求的输入 token、输出 token。缺失显示「未提供」，不计为 0 |
| ② | 1 | 已保存思考正文的字符总量，含空格和换行，按 JSON 解码后的 Unicode 字符数。缺少正文时如实标明位置 |
| ③ | 2 | 工具调用总次数、工具种类数，以及各工具调用次数 |
| ④ | 2 | 多条轨迹汇总上述三项。同一模型请求的 token 不重复累计，工具种类按名称合并去重 |

每项得分 = 该项满分 × 通过用例数 / 该用例总数。遗漏、统计错误或位置错误，对应用例不通过。样例提交里步骤是 `record/chosen_trace` 数组下标（从 0 起）。A2 样例字段为 `thought_characters`、`body_segments`、`missing_body_pointers`。

思考 token 和思考输出比例不在这 6 分里。③ 页面上已有。

## 2. 字符数和「未提供」的位置

**等样例和改完的要求，一并改。** 2026-11-13 定下。

截图里的字符数规则和 A2 草稿是同一份还没过专家评审的方案。方向是：思考正文按 JSON 解码后的 Unicode 字符数计，空格和换行算进去；缺正文要标出位置，不能整段写成「未提供」，也不能写成 0。token 仍是每条请求的输入和输出，没有用量就写「未提供」。思考 token 和思考输出比例不在这 6 分里。

字段在哪、空字符串算不算缺正文、指针怎么写，都等样例。改动面不大：数已保存的思考正文字符，并为缺正文的字段留下位置。样例到了再动。现在页面上 token 已写「未提供」，不必为这一条先改。

## 3. 多条轨迹汇总

**等正式格式再改。** 2026-11-13 定下。

要这张总表的是赛马方案，不是会议逐字稿。测试大纲和计分规则的第④项写明：展示多条轨迹的上述统计汇总结果；同一模型请求的 token 不重复累计，工具种类按名称合并去重。计分截图上③④各 2 分。①②③是单条轨迹的 token、字符数和工具次数，④把许多条收成一份汇总。

逐字稿里汪旭鸿只说了记 token 数、字符数和工具调用次数，并说这些指标不做具体约束。他没有说要一张总表，也没有说同一次请求的 token 不能算两次。他当时看的就是这份大纲。

汇总的算法是：同一次模型请求（同一次调用的身份）的 token 只进总表一次；另一次调用即使重送了前文，token 照算。工具次数相加，工具种类按名称并成一套。某次请求没有用量时，对应格子仍是「未提供」，不写成 0 加进合计。请求身份写在哪个字段上，等正式格式。现在的审阅页只有单条轨迹的统计。
