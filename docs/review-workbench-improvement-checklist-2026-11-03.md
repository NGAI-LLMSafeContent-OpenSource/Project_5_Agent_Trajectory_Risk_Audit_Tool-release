# 风险可视化审计工作台改进清单（2026-11-03）

对象：风险可视化审计工作台原型（`?variant=chain`），对应任务书 1.2「风险可视化审计工具测评」。

依据：

- 2026-10-31 项目讨论会逐字稿（`Project_5_LLM_Content_Safety_Governance_Web/docs/meetings/2026-10-31-项目讨论会/01-会议逐字稿.md`），子康演示段落 41:08–51:23；
- 1.2 评分表：数据统计指标可视化 30、思维链可视化质量 30、工具调用可视化质量 30、集成方案 10；前三项为 ≥3 位专家按统一量表盲评；
- 1.2 评测方式：组织方统一输入测试集（多风险类别、中英各半），工具对每条样本输出三个层面的可视化结果（截图/交互页面导出 + 结构化描述文件），去除单位标识后盲评。

## 一、会上为什么没讲明白

何老师的问题都在找「量表那几项在页面哪里」和「输入到输出的完整过程」，而演示是按单条轨迹的事件顺序讲的。

1. 页面上没有量表的三个层面。统计、思维链、工具调用三者的对应关系只是口头带过，画面上没有标题。何老师在 48:02 问「你这个主要是工具调用可视化是吧」。
2. 缺少端到端的例子。何老师在 49:10 要的是「智能体做什么任务、输出什么、怎么导出到界面审计」，也就是原始轨迹 → 工具 → 审计结果。演示中没有出现原始输入。
3. 演示案例的风险不直观。「跨服务令牌导出联系人」两次都被拒绝，没有实际后果，而且逐个讲 evt-03 到 evt-08 太细。
4. 英文术语多：Evidence chain、Risk path、Finding、waterfall、tool_overreach、Source label 等。
5. 课题四开场说统计指标和集成方案「一定满分」，但没说明依据，引发了何老师追问。

结论：页面必须能自己解释自己。盲评时没有讲解员，专家只看导出的截图和描述文件。

## 二、原型与评分表的差距

| 评分项 | 量表要求 | 原型现状 |
| --- | --- | --- |
| 数据统计（30） | token 数量、工具调用种类数量、思考输出比例等，尽可能丰富 | 只有 Finding / Failed calls / Tool calls / Token usage 四个数；没有思考输出比例、工具种类数，也没有测试集级汇总 |
| 思维链（30） | 来源溯源链、关键 token、风险类别分布、危险思维模式 | 只有事件树；不展示思考原文，没有关键 token 高亮、危险思维模式标签和风险来源溯源。**差距最大** |
| 工具调用（30） | 展示交互过程，定位越权、低效、错误 | 证据链 + 耗时瀑布图，做得最完整；但瀑布图以耗时为主，和证据链重复展示同一组事件 |
| 集成方案（10） | 处理 OpenAI messages 或其他主流格式，两种以上得 10 分 | 后端已支持三种格式，但页面看不出来源格式，也没有上传或切换入口 |

其他问题：

- 样本列表从第 04 条起是三种标题循环（参数不是 JSON / 凭据跨服务复用 / 重复调用），明显是模板生成；不符合「多风险类别、中英各半」。
- 页面露出「结构原型」「PROVIDER TOPIC4@0.7」等内部标记，与「去除单位标识」的要求冲突。
- 没有导出功能，产出不了评测要求的提交物。

## 三、改进清单

### P0：直接影响得分

- [ ] **按量表重组单样本视图**：分为「数据统计」「思维链」「工具调用」三个标签页或区块，标题用量表原词。
- [ ] **思维链层补全**（依赖课题四给出 token 级和段落级标注，先把 JSON 字段定下来）：
  - [ ] 完整展示思考原文，高亮关键 token；
  - [ ] 给思考段落打危险思维模式标签，例如「绕过授权」「擅自扩大范围」「失败后谎称完成」「服从注入指令」；
  - [ ] 风险来源溯源链：标出风险起于用户指令、工具返回中的注入内容，还是智能体自身，并连到后续思考和工具调用；
  - [ ] 本样本的风险类别分布。
- [ ] **工具调用层改为调用表或泳道图**：每次调用列出工具名、参数、所需权限与实际权限、返回结果，并打上「越权 / 低效 / 错误」标签（量表原词）。耗时瀑布图降为辅助视图。
- [ ] **数据统计补齐**：token 数（输入、输出、思考）、思考输出比例、工具调用次数与种类数、失败调用数、轮次数、各风险等级数量。
- [ ] **一键导出**：每条样本导出三个层面的截图（或静态 HTML）和结构化描述文件（JSON + Markdown），导出时自动去掉单位标识和内部标记。

### P1：让专家看得懂

- [ ] **测试集总览页**：风险类别分布、风险等级分布、中英文分布、工具种类与调用量、token 与思考输出比例分布，点击可跳到样本。
- [ ] **输入与输出同屏对照**：一侧原始轨迹（如 OpenAI messages JSON），另一侧审计结果；显示「来源格式：OpenAI messages / ATBench / HINTBench」。
- [ ] **格式接入入口**：支持上传或切换任意一种格式的轨迹，现场演示集成能力。
- [ ] **界面中文化，术语降噪**：Finding → 风险发现，Evidence chain → 证据链，Risk path → 风险路径，tool_overreach → 工具越权；事件编号等退到次要位置。
- [ ] **每个视图加一行读图说明**：说明这一块回答什么问题、颜色代表什么。
- [ ] **去掉内部标记**：「结构原型」「PROVIDER TOPIC4@0.7」等。

### P2：数据与演示

- [ ] **样本多样化**：替换模板化样本，覆盖提示词注入（直接 / 间接）、恶意工具、工具返回被篡改、越权、隐私泄露、低效循环、谎报完成等，中英各半。
- [ ] **准备演示案例**：选有实际后果、一句话说得清的案例，例如「网页里藏的注入指令让智能体把用户隐私发出去」，中英各一条。
- [ ] **汇报讲法**：先放 1.2 量表，每项一句话指出对应页面区域；再从原始轨迹文件开始走一遍完整流程；最后才看事件细节。

## 四、待对齐事项

- 思维链层的关键 token、危险思维模式、溯源链字段由课题四算法输出，需要和课题四确认字段与交付时间。
- 导出物格式（截图分辨率、描述文件 schema）需要等浦江的具体评测方案确认；在那之前先按「三层截图 + JSON + Markdown」准备。
