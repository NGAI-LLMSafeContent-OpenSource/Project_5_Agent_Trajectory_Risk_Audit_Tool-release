# 领域文档

本文件说明工程 skills 在探索代码库前如何读取本仓库的领域文档。

## 探索前读取

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作范围相关的 ADR

如果这些文件尚不存在，直接继续工作，不要将缺失视为错误，也不要预先建议创建。`domain-modeling` skill 会在术语或架构决策真正明确后按需创建这些文件。

## 文件结构

本仓库采用单上下文布局：

```
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-example-decision.md
│       └── 0002-another-decision.md
└── src/
```

## 使用领域词汇表中的术语

当输出内容需要命名领域概念时，例如 Issue 标题、重构方案、假设或测试名称，应使用 `CONTEXT.md` 中定义的术语，避免改用词汇表明确排除的同义词。

如果词汇表没有所需概念，应先判断是否正在引入项目中并不存在的语言；如果确实存在领域词汇缺口，则记录下来，供 `domain-modeling` skill 处理。

## 标明与 ADR 的冲突

如果建议与现有 ADR 冲突，应明确指出，而不是静默覆盖。例如：

> 与 ADR-0007（事件溯源订单）冲突，但值得重新讨论，因为……
